## Особенности API YouGile (проверено на живом API 2026-11-11)

Каждый пункт — следствие ошибки при разработке steward, а не догадка.

1. **`POST /projects` не принимает `description`** — `400 property description should not exist`.
2. **Проект без `users` создаётся без участников**: возвращается `id`, но проект не виден в `GET /projects`, а `GET /boards?projectId=…` отвечает `404 «Проект не найден»`. Поэтому в теле обязательно `users: {«id нашего аккаунта»: «admin»}`.
3. **Дубли названий нумеруются автоматически**: «Тест», «Тест (3)», «Тест (4)». Поиск по точному названию промахивается и создаёт новые сущности на каждом запуске. Нужна нормализация: точное совпадение, затем старейший вариант с суффиксом `(N)`.
4. **HTML-комментарии из описания вырезаются**: маркер `<!--plan:TD-01-->` не сохраняется, поле возвращается как `\nтекст`. Скрытая метка для идемпотентности невозможна — ключом служит заголовок задачи, а старый видимый маркер `[plan:…]` распознаётся и вычищается при обновлении.
5. **Описание — HTML**: переводы строк `\n` схлопываются в пробел, структура держится только на `<p>`, `<ul>`, `<ol>`, `<b>`.
6. **Чек-листы создаются через `checklists: [{title, items:[{title, isCompleted}]}]`** и в `POST`, и в `PUT`. Массив строк API отвергает: `each value in nested property items must be either object or array`.
7. **Признак «сделано» — флаг `completed`**, отдельных статусов у задачи нет.
8. **Вставки вида `<id>` из описания вырезаются** как HTML-тег — причём и в экранированном виде `&lt;id&gt;`. Через API их вернуть нельзя, только вручную в интерфейсе. Сравнение описаний теперь игнорирует такие места, иначе каждый прогон переписывает ту же задачу (так и случилось с P3-08 в Roadmap).
