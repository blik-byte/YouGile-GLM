# ТЗ: раздел «Заказы» (Kwork + FL.ru)

Версия 1.0 · 2026-11-11 · заказчик: владелец проекта, исполнитель: агент

Документ описывает **что** делаем и по каким критериям принимаем. Внешний вид (цвета, шрифты, сетка) в ТЗ не фиксируется — его готовит дизайнер отдельно; здесь описан состав блоков и поведение.

---

## 1. Цель и границы

**Цель.** Одно место, где видно новые заказы с двух площадок, понятно, почему заказ подходит или нет, и лежит готовый черновик отклика. Плюс — утренняя сводка, новости по теме и учёт откликов.

**Входит в первую версию:**

1. сбор заказов FL.ru (RSS) и Kwork (письма);
2. страница со списком, фильтрами и карточкой заказа;
3. автоматический отбор по критериям + ручная пометка;
4. черновик отклика по типу заказа;
5. утренний доклад (страница + Telegram);
6. новостная выжимка (страница + Telegram);
7. статистика откликов и напоминания.

**Не входит:** автоматическая отправка откликов на площадках, оплата, биллинг, мультипользовательский режим с ролями.

**Жёсткое ограничение:** ничего не отправляем на площадки от имени владельца. Только показываем и копируем.

---

## 2. Пользователь и сценарии

Один пользователь — владелец. Смотрит страницу утром и в течение дня.

1. Открывает страницу, видит новые заказы, отсортированные по приоритету.
2. По заказу читает, почему он подходит, открывает ссылку, копирует черновик, отправляет сам.
3. Отмечает статус: «откликнулся» или «не подходит».
4. Раз в день получает сводку: заказы, зависшие задачи, состояние сайтов.
5. Видит новости по AI и SEO, если есть что-то стоящее.

---

## 3. Источники данных

### 3.1. FL.ru — RSS

- Адрес: `https://www.fl.ru/rss/all.xml`
- Периодичность: раз в 20 минут (`FL_FETCH_INTERVAL_MS`, по умолчанию 1 200 000).
- Отдаёт: заголовок, ссылку, **полный текст заказа**, категорию, дату публикации.
- Бюджет часто указан в заголовке строкой «(Бюджет: 1 000 ₽)» — вытаскиваем регуляркой, иначе поле пустое.
- Кодировка в ответе: UTF-8, но текст в CDATA с двойным экранированием — декодировать обязательно.
- Дедупликация: по числу из ссылки `/projects/<id>/`.

### 3.2. Kwork — письма

- Источник: письмо от `news@kwork.ru`, тема «Новые проекты на бирже Kwork».
- Разбор уже написан (`lib/kwork-mail.js`): название, ссылка, категория, покупатель, цена.
- Полного описания в письме нет — фильтр работает по названию и категории.
- Зависимость: владелец настраивает пересылку на ящик агента. До этого раздел работает на одном FL.ru.

### 3.3. Общее

- Каждый заказ хранится с площадкой и внешним id; повторный сбор не создаёт дублей.
- Если текст заказа изменился на площадке — обновляем, но не сбрасываем статус и черновик.

## 4. Модель данных

Коллекция `leads`:

| Поле | Тип | Описание |
|---|---|---|
| `source` | `fl` / `kwork` | площадка |
| `externalId` | строка | id на площадке, уникальный вместе с `source` |
| `title` | строка | заголовок |
| `description` | строка | текст заказа (у Kwork пусто) |
| `category` | строка | категория/рубрика |
| `budget` | строка | как на площадке («30 000 ₽») |
| `budgetValue` | число | для сортировки, 0 если не указан |
| `url` | строка | ссылка на заказ |
| `publishedAt` | дата | публикация на площадке |
| `fetchedAt` | дата | когда забрали |
| `verdict` | `accept` / `unknown` / `reject` | результат фильтра |
| `verdictReason` | строка | причина отказа или список совпадений |
| `score` | число | приоритет 0–100 |
| `status` | `new` / `viewed` / `applied` / `replied` / `declined` / `archived` | состояние |
| `draft` | строка | черновик отклика |
| `draftType` | строка | `audit` / `links` / `consult` / `seo` / `generic` |
| `notes` | строка | заметка владельца |
| `appliedAt` | дата | когда отмечен отклик |

Индексы: `{source, externalId}` уникальный; `{status, publishedAt}`; `{verdict}`.

---

## 5. Отбор и приоритет

**Фильтр** — уже реализован (`config/kwork-filters.json`, `lib/kwork-filter.js`): правила «подходит / не подходит» по названию и категории, для FL.ru ещё и по описанию.

**Скоринг** (0–100) — новый слой, влияет только на порядок, не на отбор:

| Фактор | Вес |
|---|---|
| Совпадение с типом работ (аудит, ссылки, продвижение) | до 40 |
| Бюджет: 30 000+ → 30, 15 000–30 000 → 20, 5 000–15 000 → 10, ниже → 0 | до 30 |
| Свежесть: сутки → 20, трое → 10, старше недели → 0 | до 20 |
| Покупатель с историей найма (Kwork: процент найма выше 30%) | 10 |

Заказы с `verdict: reject` в основной список не попадают, но доступны по фильтру «показать отклонённые».

---

## 6. Черновик отклика

- Генерируется из `config/kwork-replies.json` по типу заказа (`lib/kwork-reply.js`).
- Для FL.ru дополнительно подставляется первая строка из описания — чтобы письмо не выглядело шаблоном.
- Хранится в заказе; владелец может править прямо на странице (правка сохраняется).
- Кнопка «пересобрать» возвращает исходный шаблон.
- Ничего не выдумываем: только факты владельца (с 2008 года, вывод из фильтров, регионы через поддомены, свой сервис аналитики).

## 7. Страница

Маршрут: `/leads`. Доступ: заголовок `X-Admin-Token`, как у дашборда; токен спрашивается один раз и хранится в браузере.

### 7.1. Состав блоков

1. **Шапка** — название раздела, счётчики: новых за сегодня, подходящих, откликов за неделю, средний бюджет.
2. **Панель фильтров** — площадка (все / FL / Kwork), вердикт (подходящие / спорные / отклонённые / все), статус, поиск по тексту, сортировка (приоритет / бюджет / дата).
3. **Список заказов** — карточки в одну колонку. В карточке: метка вердикта, заголовок, площадка, бюджет, категория, дата, первые две строки описания, кнопки «Открыть», «Скопировать отклик», «Статус».
4. **Карточка заказа (детали)** — открывается по клику: полный текст, категория, бюджет, покупатель (если есть), приоритет и из чего сложился, черновик с кнопками «скопировать» / «пересобрать» / «править», селектор статуса, поле заметки, ссылка на оригинал.
5. **Блок «Сводка»** — последний утренний доклад: заказы за сутки, зависшие задачи, состояние сайтов.
6. **Блок «Новости»** — 3–5 пунктов с источником и датой.

### 7.2. Поведение

- Список подгружается страницами по 20, «показать ещё» без перезагрузки.
- Действия не перезагружают страницу: статус и правки сохраняются сразу, с ненавязчивым подтверждением.
- Пустое состояние: «Пока нет заказов. Сбор идёт каждые 20 минут» + кнопка «Собрать сейчас».
- Ошибка сбора: плашка в шапке, старая лента остаётся.
- Адаптив: телефон — одна колонка, фильтры сворачиваются в кнопку.

### 7.3. Технические ограничения для дизайна

- Только HTML/CSS/JS без внешних библиотек и CDN — как дашборд, чтобы страница открывалась при недоступности сторонних хостов.
- Никаких тяжёлых шрифтов и фоновых видео; целевой вес страницы — до 200 КБ.
- Тёмная и светлая тема не обязательны, но если делаем — переключение на стороне клиента, без сервера.

## 8. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/leads` | список: `source`, `verdict`, `status`, `q`, `sort`, `offset`, `limit` |
| GET | `/api/leads/:id` | один заказ |
| PATCH | `/api/leads/:id` | `status`, `notes`, `draft` |
| POST | `/api/leads/:id/draft` | пересобрать черновик |
| GET | `/api/leads/stats` | счётчики для шапки |
| POST | `/api/leads/fetch` | запустить сбор вручную |

Все, кроме страницы, требуют `X-Admin-Token`. Ответы — JSON; ошибки — `{error}` с кодом 4xx/5xx.

## 9. Утренний доклад

Время: 9:00 по `REPORT_TZ`. Каналы: страница (блок «Сводка») и Telegram.

Состав:

1. новые заказы за сутки: сколько, из них подходящих, три лучших с бюджетом;
2. зависшие задачи: в работе дольше 3 дней, на проверке дольше 2 дней;
3. сайты: позиции и клики за неделю, новые ошибки из Search Console и Вебмастера;
4. одна строка «что сделать сегодня» — самое приоритетное действие.

Если данных нет — блок пропускается, пустых строк не пишем.

---

## 10. Новости

- Источники: RSS профильных изданий по AI и SEO (список настраивается в `config/news-sources.json`).
- Периодичность сбора: раз в час.
- Отбор: ключевые слова и исключения; дубли по ссылке и по заголовку.
- Формат: 3–5 пунктов, каждый — одно предложение выжимки, источник и дата. Полные тексты не храним.
- Где видно: блок на странице и одна сводка в Telegram вместе с утренним докладом.

---

## 11. Конверсия и напоминания

**Считаем:** откликнулся → ответил → взял в работу. Проценты по неделям и по типу заказа.

**Напоминания:** заказ со статусом `applied` без изменения 2 дня — подсветка в списке и строка в утреннем докладе. Через 7 дней предлагается «архивировать».

## 13. Этапы и критерии приёмки

**Этап 1. Сбор FL.ru.** RSS разбирается, заказы попадают в базу, дубли не создаются, ошибки сети не роняют сервис.
*Приёмка:* после запуска в базе ≥ 20 заказов; повторный сбор через 20 минут не добавляет уже известные; лог показывает число новых.

**Этап 2. Страница.** Список, фильтры, карточка, смена статуса, копирование черновика.
*Приёмка:* страница открывается на телефоне и десктопе; фильтр по площадке и вердикту работает; статус сохраняется после перезагрузки; кнопка «скопировать» даёт полный текст отклика.

**Этап 3. Утренний доклад.** Приходит в 9:00 в Telegram и виден на странице; пустые блоки не выводятся.
*Приёмка:* доклад за день с реальными числами; при отсутствии данных — короткое «новых заказов нет».

**Этап 4. Новости.** Сбор по расписанию, выжимка 3–5 пунктов, дубли отсекаются.
*Приёмка:* в ленте только свежие материалы (сутки), ссылки рабочие.

**Этап 5. Конверсия и напоминания.** Метрики на странице, подсветка зависших откликов.
*Приёмка:* цифры совпадают с ручным подсчётом по десяти заказам.

## 14. Открытые вопросы

1. Нужен ли отдельный адрес страницы (поддомен) или хватит `/leads` на текущем?
2. Публиковать ли список заказов наружу — нет, страница закрыта токеном; подтвердить.
3. Список новостных источников — предложу 5–6, владелец вычеркнет.
4. Нужен ли экспорт заказов в CSV для архива.
