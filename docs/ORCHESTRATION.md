# Оркестрация: роли, конвейеры, контракты

Документ фиксирует, **как** устроено взаимодействие агентов. Задачи и их статусы живут в YouGile (`plans/ai-agents-yg.json` → доска Roadmap), состояние проекта — в `docs/STATE.md`, доступы — в `docs/ACCESS.md`. Здесь только архитектура.

## Что считается оркестрацией в этом проекте

Не «чат, который сам решает», а **детерминированный маршрут**: код ведёт шаг за шагом, модель отвечает за содержание внутри шага. Три слоя:

1. **Конвейер** (`lib/workflows.js`) — какие шаги и в каком порядке, где остановиться и спросить человека.
2. **Роль** (`prompts/*.js`) — что модели разрешено делать на этом шаге и в каком формате отвечать.
3. **Гейт** (`lib/approvals.js`) — внешнее действие (публикация, заявка, изменение чужого ресурса) выполняется только после одобрения владельцем.

Свободный агент (`ai-agent.js`, до 25 шагов) остаётся для задач, где маршрут заранее неизвестен, но и он заканчивается не действием наружу, а результатом в «На проверку».

## Принципы

1. **Оркестратор — сильнейшая доступная модель.** Экономить на воркерах, не на оркестраторе: ошибка в распределении задач дороже потраченных токенов.
2. **Один агент = одна атомарная операция с проверяемым результатом.** Тема → одобрение → статья + ТЗ → одобрение → публикация, а не «сделай статью целиком».
3. **Контракты структурированные.** Между шагами передаётся JSON по схеме, не свободный текст: это отсекает половину потерь при передаче.
4. **Человек в контуре на внешних действиях — навсегда.** Kwork, публикация, письма клиентам: агент готовит черновик, жмёт человек.
5. **Контекст не таскать целиком.** Воркер отдаёт оркестратору `digest` (выжимку), а не простыню страницы.
6. **Лог каждого прогона.** Что взял, что вернул, сколько токенов, где упал. Без этого отладка превращается в гадание.
7. **Рецензент — на другой модели, чем автор.** Самопроверка той же моделью почти не ловит её собственные ошибки.

## Роли и модели

Решение владельца: локальные модели живут на ПК, в проде на Render — только облачные. Render — 512 МБ RAM без GPU, локальную модель там не запустить.

| Роль | Модель | Где | Задача | В коде |
|---|---|---|---|---|
| Оркестратор | GLM-4.5 Flash → фолбэк Qwen 9B (локально) | Render | распределение задач, тяжёлые выводы, финальная редактура | `lib/glm-client.js`, `lib/task-planner.js` |
| Планировщик | GLM-4.7 Flash | Render | план из 3–7 шагов под запрос | `GLM_MODEL_PLANNER` |
| Исполнитель | GLM-4.5 Flash | Render | шаги с инструментами | `ai-agent.js`, `tools.js` |
| Рецензент | другая модель, не автор шага | Render / ПК | приёмка результата до «На проверку» | не реализован |
| Воркер «подай-принеси» | Qwen3.5-4B Q8 | ПК | суммаризация RSS, извлечение по схеме, форматирование | не реализован |
| Зрение | GLM-4.6V Flash / Gemma 3 4B | Render / ПК | разбор скриншотов, сверка картинки с ТЗ | `analyze_image` |
| Классификация | Llama 3.2 3B / Qwen 4B | ПК | теги, роутинг, отнесение задачи к конвейеру | `prompts/index.js` (сейчас по ключевым словам) |

Роли из плана, которых пока нет в коде: SEO-монитор (Kwork), Контентщик, Публикатор, Ньюс-монитор, SEO-аналитик (GSC/Вебмастер).

Про 2-битные кванты и «эксперименты ради эксперимента»: в оркестрацию берём только модели с предсказуемым tool-calling. Если классификация ошибается, ломается весь маршрут, а не один шаг.

## Конвейеры

**Уже работают:**

| Конвейер | Вход | Гейт | Выход |
|---|---|---|---|
| Семантика | «Собери черновик семантики по группе X» | частотности владельца + `/approve` | `.xlsx` в хранилище, страницы в MODX |
| Публикация страницы | одобренный черновик + кластер | `create_only` в коннекторе | черновик `published=0` в MODX |
| SEO-аудит | URL | нет (read-only) | балл, находки, рекомендации |
| Документы | любой запрос на файл | нет (read-only) | docx/xlsx/csv/md/json + ссылка |

**Запланированы (колонки Roadmap):** утренний доклад GSC/Вебмастер, RSS-монитор новостей, монитор конкурентов, PageSpeed-отчёт, контент-пайплайн с публикацией, Kwork-монитор полуавтоматом.

Правило очерёдности: сначала read-only (отчёты, выжимки) — они прощают ошибки модели и обкатывают инфраструктуру; только потом действия наружу. Kwork и Wordstat — сразу полуавтомат: там капчи, антифрод и отсутствие публичного API, автопилот сожжёт аккаунт.

## Точки одобрения

| Действие | Кто одобряет | Механизм |
|---|---|---|
| Создание страниц по черновику семантики | владелец | `/approve <id заявки>` в Telegram |
| Публикация (снять `published=0`) | владелец | вручную в MODX; в режиме `full` — заявка |
| Размещение отклика на Kwork | владелец | кнопка «Разместить», текст копируется вручную |
| Ответ клиенту, счёт, акт | владелец | черновик в комментарии задачи |
| Изменение чужого ресурса в MODX | владелец | заявка, `lib/approvals.js` |

## Контракт между шагами

Единый JSON, поля обязательные; отсутствие поля — ошибка шага, а не повод импровизировать.

```json
{
  "step": "semantics_draft",
  "taskId": "uuid",
  "status": "ok | needs_input | failed",
  "digest": "1-3 предложения: что сделано",
  "artifact": { "type": "xlsx", "url": "https://..." },
  "needsApproval": { "id": "a5bc8f21", "action": "create_pages" },
  "facts": [ { "claim": "...", "source": "https://..." } ],
  "tokens": { "in": 0, "out": 0 },
  "error": null
}
```

Правила: `facts` без `source` не принимаются; `status: failed` обязан содержать `error`; `digest` — не больше трёх предложений, полный текст идёт в документ.

## Логи прогонов

Уже есть: коллекция запусков в MongoDB (`runs`), страница `/report/:taskId`, дашборд с шагами и вызовами инструментов. Не хватает: расхода токенов на шаг и стоимости прогона, а также явной причины остановки. Добавляется вместе со steward.

## Чего не хватает для оркестрации v1

1. **Steward** — управление проектами, досками, колонками и задачами из плана (`lib/steward-plans.js`, `board-steward.js` по Roadmap). Без него каждый новый проект заводится руками.
2. **Рецензент** на модели, отличной от автора, перед переводом в «На проверку».
3. **Watchdog и «пинки»** — задачи для людей: если задача висит дольше срока, бот напоминает владельцу и спрашивает статус. Задачи, которые агент выполнить не может, должны доходить до человека сами.
4. **Контракты** между существующими шагами (сейчас часть передачи идёт текстом).

## Анти-паттерны

- Автопилот на Kwork и Wordstat.
- Длинные цепочки «решил → сделал → проверил» на 4B–9B: локальные модели тянут короткие атомарные операции.
- Свободный текст вместо JSON между агентами.
- Свой дашборд раньше, чем накопилась история: YouGile + Telegram закрывают потребность дешевле.
- Проверка результата той же моделью, что его создала.
